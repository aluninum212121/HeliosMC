# Воспроизведение ML-исследований HeliosMC

Работайте из корня проекта после установки зависимостей по README.
Используются NumPy, SciPy, Matplotlib, Numba при наличии и pytest для тестов.
Физический движок и материальные справочники не модифицируются
исследовательским скриптом.

Окружение сохранённого полного эксперимента (из `experiment_config.json`):

| Компонент | Версия |
| --- | --- |
| Python | 3.14.4, 64 bit |
| NumPy | 2.4.4 |
| SciPy | 1.18.1 |
| Numba | 0.67.0 |
| ОС | Windows 11, build 26200 |

`OMP_NUM_THREADS` и `OPENBLAS_NUM_THREADS` были равны `1`.
Это запись выполненного окружения; текущий набор зависимостей указан в README.
Побитовое совпадение на других версиях библиотек не гарантируется.

## Запуск v2

В PowerShell задайте ограничения потоков для воспроизводимых CPU-измерений:

```powershell
$env:PYTHONDONTWRITEBYTECODE='1'
$env:OMP_NUM_THREADS='1'
$env:OPENBLAS_NUM_THREADS='1'
py -B -m benchmarks.ml_baseline quick --schema v2 --output benchmarks/results/ml_multivariate_v2/quick_new --budget-seconds 300
py -B -m benchmarks.ml_baseline full --schema v2 --output benchmarks/results/ml_multivariate_v2/full_new --budget-seconds 300
```

Замените `py` на команду доступного Python, если launcher не работает.
Никакие пакеты автоматически не устанавливаются.

Три входа v2 в строго таком порядке:

| Имя | Единица | Допустимый замкнутый интервал |
|---|---|---|
| `thickness_cm` | cm | [0.1, 3.0] |
| `absorption_rate` | 1/cm | [0.02, 1.2] |
| `scattering_rate` | 1/cm | [0.0, 2.0] |

Это абстрактная синтетическая среда, без идентичности реальному веществу.
Источник фиксирован в x=0, mu=1. Дополнительный `source_mu` как ML-вход не
реализован. Для массивов `(n, p)` вызывающий код обязан соблюдать сохранённый
порядок; произвольную перестановку без имён невозможно распознать по значениям.
API `inputs(..., feature_spec=..., feature_names=...)` проверяет именованный
порядок. CLI формирует строку из именованных аргументов.

Quick формирует 60 групп × 3 × 1000 историй. Full по стоимости собственного
пилота выбирает 300–900 групп, три повтора по 8000 историй. Число групп не
подбирается по test-качеству. LHS seed, разбиение, архитектуры, допуски,
MC seed и план дополнительных исследований записываются до обучения в
`experiment_config.json`; группы также находятся в `splits.json`.

`--budget-seconds` ограничивает **один вызов основной генерации**, а не время
всего исследования. Есть отдельные конечные стадии: 12 поисковых MLP-fit,
ограниченные линейные fit, 15 size-study случаев и 12 ablation-случаев с
повторным использованием полных моделей, high-precision и noise-диагностика.
Каждый MLP-fit ограничен 2500 итерациями и 7500 вызовами функции, без
бесконечного автоматического поиска. Оптимизация и подготовка графиков могут
потребовать больше времени, чем сама генерация MC.

## Возобновление и сохранность результатов

После обычного прерывания/исчерпания бюджета повторите ту же команду и тот же
каталог. Код и схема должны совпадать с сохранёнными хешами. Полные родные
bundles переиспользуются, их seed не меняются; accumulated generation wall
записывается в `generation_progress.json`. Поисковые и дополнительные fit
имеют checkpoints `training_trials.json`, `study_models.json`.

Нативный ZIP не является транзакционным хранилищем: аварийное завершение
процесса во время записи может повредить центральный каталог или оставить
неполный bundle. Автоматическое восстановление такого повреждения не
выполняется. Сохраните проблемный каталог и выберите новый; скрипт не подменяет
данные успешно рассчитанными. Изменение исходного скрипта во время незаконченного
прохода также требует нового каталога для генерации. Диагностику старого
прохода не удаляйте.

Существующий `manifest.json` означает завершённый вычислительный проход;
quick/full откажутся его перезаписывать. Для нового эксперимента задайте новое
имя каталога. Режимы quick и full относятся к независимым запускам. Quick служит
проверке кода, а не дополнительным train для full. Пробные результаты quick
не входят в публичный набор; приведённые команды создают их заново.

## Предсказание и повторная оценка без обучения

```powershell
py -B -m benchmarks.ml_baseline predict --output benchmarks/results/ml_multivariate_v2/full --thickness 1.5 --absorption-rate 0.4 --scattering-rate 1.0
py -B -m benchmarks.ml_baseline evaluate --output benchmarks/results/ml_multivariate_v2/full
```

Predict/evaluate читают численные JSON-параметры и не запускают fit. Все три
именованных параметра v2 обязательны. Выход за сохранённые интервалы вызывает
отказ, а не надёжно маркированное предсказание. Выход самой сети за [0,1]
сохраняется в результатах без clipping; такая ошибка не исправляется скрыто.

Evaluate без `--dataset` повторно читает native-архив основного эксперимента
и оценивает исходный held-out test, не создавая новый тестовый набор.
`--dataset <каталог>` позволяет подать другой native-датасет с совместимыми
материалом, постановкой и схемой входов. Пересечение физических групп с
train/validation запрещено. `diagnostic_experiments.zip` содержит несколько
диагностических задач и читается в `diagnostic_v2`, а не как основной dataset.

## Старые одномерные модели v1

Полный исходный набор v1 сохранён в `benchmarks/results/ml_baseline/full`.
Он также нужен регрессионной проверке загрузки старой модели.
Новая схема не применяется к ним автоматически. Для v1 используется старый
водный reference-профиль; можно задать только толщину:

```powershell
py -B -m benchmarks.ml_baseline predict --output benchmarks/results/ml_baseline/full --thickness 1.5
py -B -m benchmarks.ml_baseline evaluate --output benchmarks/results/ml_baseline/full
py -B -m benchmarks.ml_baseline full --schema v1 --output benchmarks/results/ml_baseline/full_new
```

Для точного исторического исходного текста скрипта и отчёта имеется Git-версия
`d8c9d37`. Например, `git show d8c9d37:benchmarks/ml_baseline.py` выполняет
только чтение. Новая реализация сохраняет контракт v1 и загрузку её весов,
однако текущий script SHA256 отличается. Повторная генерация через новые
источники имеет собственный хеш и не должна называться побитовым повтором
исторического программного окружения. При недоступном старом raw ZIP оценка
через native-архив потребует его локального восстановления; predict работает
по сохранённой JSON-модели.

## Отчёт, рисунки и проверка чисел

После завершённого full и записи результатов тестирования:

```powershell
py -B -m benchmarks.ml_baseline report --output benchmarks/results/ml_multivariate_v2/full
```

Команда обновляет `docs/ML_RESEARCH_REPORT.md` по сохранённым артефактам,
создаёт `report_tables.json`, проверяет 13 табличных блоков и 20 основных
значений comparison.csv против metrics.json и записывает
`report_consistency.json`. Она не обучает модели. Текст отчёта предназначен
для авторского редактирования; повторный report перегенерирует его, поэтому
авторскую редакцию следует сначала сохранить отдельно.

PNG в `figures/` сохраняются Matplotlib в 300 dpi из фактических метрик,
предсказаний и MC-наблюдений. Парные bootstrap-интервалы и seed study вычисляются
на уровне конфигураций. Графики среза содержат наблюдённую сетку при s=1 см⁻¹.
Предсказательная неопределённость MLP отдельно не калибровалась.

`manifest.json` содержит SHA256 каждого результата. Проверить его без новых
зависимостей можно через стандартные `hashlib`, `json`, `pathlib` Python.
Checksum подтверждает согласованность, но не доверенного автора. Raw ZIP и
крупные checkpoints остаются локально и исключены `.gitignore`.
Поэтому свежий клон содержит JSON-модели для predict, но для evaluate
потребуется исходный `experiments.zip` или новый набор, полученный генерацией.

## Тесты

```powershell
py -B -m pytest tests/test_ml_baseline.py -q -p no:cacheprovider
py -B -m pytest -q -p no:cacheprovider
```

Тесты проверяют v1/v2, градиенты конечными разностями, named order,
scaler, совместимость весов, полином, постоянные входы, native-экспорт,
агрегацию, групповое разбиение, возобновление и CLI. Нативный GUI-тест остаётся
отдельным opt-in и может быть пропущен. Факт прохождения тестов не означает
физической валидации учебной модели.

## Зафиксированное выполнение 19 ноября 2026 года

Основной каталог — `benchmarks/results/ml_multivariate_v2/full/`.
Получены 900 групп, 2700 запусков и 21,6 млн историй основного датасета;
разбиение 630/135/135. Генерация фактически возобновлялась после лимита
300 секунд, с сохранением одинакового плана и seed. Все 65 ML-тестов прошли
до основного эксперимента. Полная проверка: 396 тестов и 2 подтеста прошли,
1 opt-in GUI-тест пропущен; pytest сообщил 103,11 с.

После расчётов исправлены только пределы осей наблюдаемого среза и пояснения
отчёта о некорректных вероятностях/диагностических ошибках. Значения моделей,
метрик и данных не изменялись. `experiment_config.json` хранит хеш исходников
именно выполненного вычислительного прохода; `postprocessing_revision.json`
отдельно хранит исходный и текущий хеш генератора представления и контрольные
суммы неизменившихся численных артефактов. Поэтому текущий script SHA256
отличается от вычислительного снимка без необходимости повторять 21,6 млн
историй ради правки рисунка. Новое полное воспроизведение через текущий
скрипт должно использовать новый каталог и сохранит собственный хеш.

## Редакционная подготовка репозитория

После зафиксированного исследования очищены комментарии и документация.
Хеши в конфигурациях, моделях и исторических проверках сохранены без подмены.
Их отличие от текущих исходников ожидаемо даже при неизменной математике.
Для новых расчётов используйте новый каталог: возобновление старого прохода
при изменившемся коде отклоняется. Чтение сохранённой модели для predict
и проверка таблиц отчёта не требуют переобучения.

Исторический `report_consistency.json` содержит хеш редакции отчёта,
проверенной при выполнении исследования. После редакционных правок текущего
текста этот хеш может отличаться; численные табличные блоки сохранены
и повторно проверены против исходных JSON/CSV.
